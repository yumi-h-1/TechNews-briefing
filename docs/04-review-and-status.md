# 04. 검수 기준과 기존 초안 상태

## 인수 기준

| 영역 | 확인할 결과 |
|---|---|
| 대상 | 수신자는 사용자 본인 한 명 |
| 내용 | 영국·미국·한국 IT·AI 동향이 구분됨 |
| 언어 | 영국·미국 영어, 한국 한국어 |
| 한국 원문 | 한국어 주요 언론사이며 한국 영문 매체로 대체되지 않음 |
| 국가 | 사건의 관련 국가가 명확하고 매체 소재지만 보고 배치하지 않음 |
| 근거 | 원문에 없는 수치·발언·사실을 추가하지 않음 |
| 의미 설명 | 사실과 해석을 구분하고 과도한 전망을 피함 |
| 중복 | 같은 사건의 다중 매체 보도와 기존 발송을 구분함 |
| 빈 결과 | 뉴스 부족·수집 실패·검토 탈락을 구분해 표시함 |
| 시간 | 합의된 오전 8시 정책과 영국 서머타임을 지킴 |
| 서버 | 개인 컴퓨터를 꺼도 실행됨 |
| 추적 | LangSmith에서 실제 그래프·모델 호출을 확인함 |
| 비용 | 실행 수·재시도·토큰·서버 비용을 확인할 수 있음 |
| 장애 | 재실행·중단·응답 불확실 시 중복 방지와 복구 절차가 있음 |

## 기존 초안 파일 지도

아래 경로는 `reference/prototype/` 기준이다.

| 파일 | 현재 책임 |
|---|---|
| `briefing/config.py` | 환경변수·수신자·시간대 설정 |
| `sources.json` | 7개 RSS 소스와 허용 도메인 |
| `briefing/news.py` | RSS 수집, 날짜·키워드·URL 처리, 공개 본문 조회 |
| `briefing/models.py` | 기사·선정·요약·검토·그래프 상태 형식 |
| `briefing/agent.py` | 모델 지시, 선정·본문 조회·작성·검토·수정 그래프 |
| `briefing/render.py` | HTML·일반 텍스트 메일 |
| `briefing/storage.py` | SQLite 발송본·기사 이력 |
| `briefing/mail.py` | Resend 또는 SMTP 발송 |
| `briefing/app.py` | 명령 실행, 생성·발송 제어、스케줄러 |
| `briefing/demo.py` | 가상 기사 예시 |
| `tests/test_briefing.py` | 모의 모델·메일 서비스 기반 테스트 |
| `Dockerfile`, `render.yaml` | 미검증 서버 배포 초안 |
| `.env.example` | 비어 있는 인증정보 설정 예시 |

## 이전 대화에서 확인한 사실

- 로컬 Python 환경에서 18개 테스트 통과
- 영국 서머타임·전환일, 재시도·중복 발송 방지, 그래프 분기·수정 제한, HTML escaping 등을 모의 데이터로 검증
- 공식 RSS 7곳의 HTTP 200 및 RSS 항목 응답 확인
- 마지막 수집기 점검에서 후보 37개 수집, 소스 오류 안내 없음. 이는 당시 한 번의 실행 결과이며 현재 값이나 국가별 기사 수를 보장하지 않음
- 가상 기사 기반 화면 예시 생성
- 컨테이너 빌드는 Docker 데몬 미기동으로 수행하지 못함
- API 키를 연결한 실제 모델 호출·LangSmith 추적·메일 발송·받은편지함 도착·서버 배포는 수행하지 않음
- Render 연결 제안은 있었지만 계정 연결·사용자 서비스 선택·배포는 확인되지 않음

이번 이관 작업에서는 위 검증을 재실행하지 않았다. 과거 검증 기록을 ‘지금 다시 통과했다’고 읽지 않는다.

## 사용자 리뷰에서 우선 볼 부분

다음은 확정 결함 목록이 아니라 초안을 최종 설계로 채택하기 전에 확인할 논점이다.

1. **시간 정책:** 현재는 08:00에 생성 시작. 08:00 도착 목표라면 생성과 발송 시간을 분리해야 함.
2. **수집 범위:** 소스당 12개와 광범위한 한국어 산업·과학·경제 피드로 중요 기사를 놓칠 수 있음.
3. **최신성:** 발행일/수정일 처리와 피드의 오래된 내용, 부분 소스 실패 후 다음 날 복구 범위를 검토.
4. **사건 중복:** 모델이 생성한 event_key만으로 의미가 같은 사건을 안정적으로 구분하는지 확인.
5. **업데이트 허용:** 동일 event_key는 차단되므로 기존 사건의 중요한 새 업데이트를 허용하려는 기획과 정합성을 검토.
6. **검토의 한계:** 같은 모델의 작성·검토와 짧은 근거 인용 검사는 사실 검증을 보장하지 않음. 잘못된 수치·국가 배치 사례를 별도 평가.
7. **조회 품질:** 실제 본문 추출, robots.txt 실패, 유료벽·로그인 문구, RSS 근거 부족을 어떻게 구분하는지 확인.
8. **발송 복구:** `sending`·`uncertain` 후 운영자가 접수 로그를 보고 안전하게 복구할 수 있는지 확인. 현재 전용 복구 UI나 명령 없음.
9. **운영 메일:** Resend 기본 발신자는 테스트 목적. 운영용 발신자·도메인·계정과 비용은 미정.
10. **서버·저장:** 영구 디스크 권한, 단일 worker 가정, 재배포와 장애 복구, Docker 빌드와 종료 처리 검증 필요.
11. **관측·예산:** 실제 토큰·비용 추적, 일일 실패 상한, 예산 초과 정책과 실패 알림 경로가 필요한지 결정.
12. **구성 분리:** 수신 주소가 문서와 코드·설정에 여러 번 들어 있음. 개인용 제약을 유지하면서 설정의 단일 출처를 만들지 검토.

## 초안 명령의 의미

`demo`는 가상 예시, `sources`는 RSS 수집 확인, `preview`는 실제 AI 생성이지만 메일 미발송, `send`는 즉시 실제 발송, `serve`는 예약 실행이다. 첫 리뷰에서 실행할 필요는 없다. 실행할 때는 각 명령의 외부 효과와 설정을 먼저 확인한다.
