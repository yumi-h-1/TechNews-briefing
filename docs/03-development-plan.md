# 03. 개발 작업 명세

사용자가 단계별로 구조와 코드를 리뷰할 수 있는 크기로 개발한다. 첫 작업은 요구사항과 설계 차이 검토이며, 기존 초안 전체를 곧바로 최종 코드로 채택하는 작업이 아니다.

## 0단계: 설계 리뷰

- 확정 요구사항과 기획 제안, 초안 선택을 구분한다.
- 모듈 구성, 상태 모델, 에이전트 분기, 장애 흐름을 설명한다.
- 오전 8시의 의미와 운영 예산처럼 구현에 영향을 주는 결정을 정리한다.
- 참고 구현을 재사용할지, 부분적으로 재사용할지, 새로 작성할지 근거를 제시한다.

**완료 조건:** 사용자가 흐름과 선택 이유를 이해하고 첫 개발 범위를 결정할 수 있다.

## 1단계: 수집과 저장

- 공식 소스와 피드 주소, 한국어 출처 조건을 검증한다.
- 수집 대상 기간과 날짜 처리, 중복 URL 처리, 소스별 오류 기록을 구현한다.
- 모델 없이 기사 후보를 확인할 수 있게 한다.
- 소스별 수집 개수와 제외 이유를 확인할 수 있게 한다.

**완료 조건:** 영국·미국·한국 후보를 수집할 수 있고 오래된 기사·날짜 불명 기사·소스 실패 처리 결과를 설명할 수 있다. 매체별 수집 성공과 국가별 뉴스 충분성을 혼동하지 않는다.

## 2단계: LangGraph 편집 에이전트

- 국가 분류와 관련성·중요도 판단을 구조화한다.
- 모델이 추가 근거 조회를 선택하는 분기를 만든다.
- 승인·수정·제외 경로와 반복 횟수 제한을 둔다.
- 영국·미국 영어, 한국 한국어 및 한국어 원문 조건을 검증한다.
- 과거 기사와 같은 사건을 여러 번 보내지 않도록 설계한다.

**완료 조건:** 근거 충분/부족, 수정 성공/실패, 후보 없음의 사례가 예측 가능한 경로로 끝난다. 생성 결과가 없을 때 원인도 구분한다.

## 3단계: LangSmith와 품질 평가

- 그래프와 모델 실행의 실제 추적을 연결한다.
- 국가 분류, 한국어 출처 준수, 중복 여부, 요약 근거, 언어 준수 사례를 평가한다.
- 토큰·실행 시간·비용과 모델 변경 전후 차이를 기록한다.
- 인증정보와 수신자 주소가 추적에 들어가지 않는지 점검한다.

**완료 조건:** 실제 실행 1건 이상이 LangSmith에 나타나고 사용자가 각 단계의 결과와 사용량을 확인할 수 있다. 모의 모델 테스트와 실제 뉴스 품질 평가를 별도로 기록한다.

## 4단계: 메일 미리보기와 발송

- 실제 뉴스 미리보기와 가상 데이터 예시를 명확히 구분한다.
- HTML·일반 텍스트, 기사 링크, 발행일, 소스 누락 안내를 만든다.
- 실제 발송 전 본문 저장과 고유 발송 식별값을 설계한다.
- 성공·명확한 실패·접수 여부 불확실 상태를 구분한다.
- 사용자 본인 주소 외 발송을 방지한다.

**완료 조건:** 사용자 본인 주소에 테스트 메일이 도착하고, 재실행·시간 초과·발송 중 종료 시 중복/누락 처리 결과를 확인한다. 서비스 접수와 받은편지함 도착을 구분해 기록한다.

## 5단계: 서버와 매일 실행

- 선택된 서버 환경에서 빌드·기동·비밀 설정을 검증한다.
- 영국 현지 시간과 서머타임 전환을 처리한다.
- 재시작·재배포 후 발송 이력이 유지되는지 확인한다.
- 실패 감지와 수동 복구 절차를 준비한다.
- 서비스와 월 비용이 정해진 뒤 배포한다.

**완료 조건:** 개인 컴퓨터를 꺼둔 상태에서 실제 예약 발송을 확인한다. 다음 날 발행본도 중복 없이 도착하고 실패 시 상태를 확인할 수 있다. 한 번의 수동 발송 성공만으로 완료 처리하지 않는다.

## Codex 작업 보고 형식 제안

단계마다 변경 내용, 설계 이유, 사용자에게 필요한 검토 지점, 수행한 검증, 남은 한계를 간결히 전달한다. 사용자가 선택하지 않은 서비스나 기준을 확정된 요구사항으로 기록하지 않는다.
