# 구현 검토 및 진행 기록

## 현재 요청과 자료의 구분

현재 사용자는 기획 순서에 따른 제작을 요청했다. CODEX_HANDOFF.md의 첫 응답 형식과 구현 중지 요청은 이전 채팅에 전달하려던 문구이며 현재 요청으로 취급하지 않는다. 다만 단계별로 이해하고 리뷰할 수 있는 크기로 진행한다는 제품 개발 방향은 유지한다.

확정 요구사항은 단일 수신자, 매일 Europe/London 오전 8시, 영국·미국 영어 / 한국 한국어, 한국어 주요 언론 출처, 서버 운영, LangGraph / LangSmith다. 기사 수, 서비스, 비용, 장애 복구 시한, 오전 8시 생성 또는 발송 기준은 미정이다.

## 0단계 설계 검토

수집 → 날짜·URL 정규화 → 후보·실행 보고서 저장 → LangGraph 선별 → 필요 시 근거 조회 → 작성 → 검토 → 제한된 수정 → 승인 기사 편집 → 본문 저장 → 발송 → 접수 상태 저장으로 나눈다. 발송을 그래프에서 분리하고 수신 주소와 비밀키를 그래프·추적 상태에 넣지 않는다.

수집은 사건 국가를 확정하지 않는다. 영국 매체에서 가져왔다고 영국 뉴스로 분류하지 않으며, 언론 출처의 언어와 사건 국가를 구분한다. 이후 그래프가 직접적인 지역 관련성을 근거와 함께 판단해야 한다. 한국어 매체라는 설정만으로 각 기사 원문의 언어 검증까지 완료된 것은 아니다.

추가 근거가 필요한 경우 허용된 기사 ID로만 조회한다. 검토 결과가 부족하면 수정 횟수 내에서 재작성하고 여전히 부족하면 제외한다. 수집 실패·유효 후보 없음·검토 탈락을 구분한다. 과거 발송 이력과 비교하되 중대한 후속 사건의 허용 기준은 별도 구현한다.

### 기존 초안 재사용 판단

- 후보 소스 7곳과 URL 추적 인자 제거, 도메인 제한 개념은 재사용한다. 소스는 여전히 변경 가능한 후보 목록이다.
- 초안의 전체 코드를 운영 코드로 복사하지 않는다. 기존 고정 국가별 3개, 제공업체, 소스당 12개 등의 선택은 확정 요구사항이 아니다.
- 기존 수집기는 날짜 불명·기간 제외·주제 제외를 조용히 버린다. 새 수집기는 제외 이유와 소스별 상태를 저장한다.
- 기존 updated 대체는 오래된 기사를 최신 기사로 볼 가능성이 있어 발행일 불명으로 구분한다.
- 기존 저장소는 주로 발송 기록을 다룬다. 수집 실행·후보·실행별 연결은 독립적으로 저장한다.
- 기존 그래프의 구조는 다음 단계의 참고 자료다. event_key 동일 차단은 중대한 업데이트 허용 요구와 충돌하며 인용 문자열 일치만으로 사실 정확성을 보장할 수 없다.
- 기존 발송·배포 초안은 미채택 상태다. 동시 실행, 발송 결과 불확실 상태 복구, 영구 저장을 검증해야 한다.

## 1단계 구현

Python 표준 라이브러리만으로 RSS / Atom 수집과 SQLite 저장, 명령행 실행을 구현했다. 모델 및 메일 서비스 설정 없이 실행할 수 있다.

- 기간은 `(since, until]`, 시간대가 있는 시각만 허용하며 UTC로 정규화한다.
- 첫 실행은 최근 24시간이다. 현재는 수집 단계만 있으므로 마지막 수집 시각을 마지막 발송 시각으로 취급하지 않는다. 발송 기록을 연결할 때 후속 수집 기간을 결정해야 한다.
- 소스별 날짜 불명, 오래됨, 미래 날짜, 유효하지 않은 기사, 주제 불일치, 수량 제한, 중복 URL을 집계한다.
- URL은 HTTPS와 등록 도메인만 허용하고 리디렉션도 검사한다. 응답은 2 MB, 요청별 대기는 20초로 제한한다.
- 실행별 보고서와 후보 스냅샷, URL 기반 후보 ID를 저장한다. 재수집 시 후보는 갱신하되 과거 실행의 보고서는 유지한다.
- 소스 실패가 있어도 나머지 후보를 저장한다. 모든 소스 실패 시 종료 코드 2를 반환한다.
- 후보 상한 50은 수집 범위를 과도하게 줄이지 않기 위한 임시 설정이며 CLI로 조절할 수 있다. 최종 메일 기사 수와 무관하다.

## 남은 단계와 결정

1. LangGraph 편집 및 근거 조회·수정·제외 경로 구현. 공급자와 모델, 예산 결정 필요.
2. 실제 LangSmith 연결과 품질 평가. 비밀 설정은 로컬 환경변수 또는 서버 secret으로 관리.
3. HTML / 텍스트 미리보기와 발송 상태 관리. 발신 계정·도메인과 서비스 결정 필요.
4. 서버 배포와 예약 실행. 오전 8시 정책, 서버 예산, 장애 복구 정책 결정 필요.

현재 단계에서 실제 모델 호출, LangSmith 추적, 메일 발송, Docker 빌드, 배포 및 예약 발송은 수행하지 않았다. 전체 프로젝트 완료 상태가 아니다.


## 후속 구현: 사용자 결정 반영

사용자가 오전 8시 발송 목표와 OpenAI·Resend·Render 준비 방향을 선택했다. 이후 LangGraph 분기, 근거 조회 상태, 제한된 수정, 근거가 있는 후속 사건 처리, LangSmith·토큰 사용량 연동, HTML/텍스트, 저장 후 발송, 불확실 상태 복구, 사전 생성 스케줄과 Docker/Render 설정을 구현했다. 위의 1단계 시점 기록과 구분하며, 현재 검증 범위 및 남은 운영 작업은 [운영 안내](06-operations.md)를 기준으로 한다. 전체 인수 조건은 아직 충족하지 않았다.
